## Selected task

**R0-ADR-003 — Privacy threat model and data-class inventory.**

Technical Architecture v1.5 §38 R0.1 acceptance: every report/config field maps to an allowed, prohibited, or sensitive class; the canary strategy covers every prohibited class.

## Requirement/specification mapping

- FR-CFG-008 — this task implements the sensitivity/classification slice for every baseline configuration field. Defaults, ranges, dynamic/static status, and affected-capability metadata remain R1-CFG-001 work.
- SEC-012 — every prohibited class has a synthetic canary strategy covering logs, reports, caches, temporary files, bundles, and viewer exports.
- Functional Specification v1.5 §15 — prohibited-by-default classes, safe bounded metadata, redaction-before-interning, and keyed-HMAC guidance.
- Technical Architecture v1.5 §30–31 — baseline bundle/report and core configuration examples used for field coverage.
- Technical Architecture v1.5 §37.2–37.3 — global task contract and stage gate.

## Implementation

- Added `privacy/data-class-inventory.json` as the machine-readable privacy source of truth.
- Added an inventory schema marker and a stdlib validator with hard file/class/field/text bounds.
- Classified 114 v1.5 baseline configuration fields and 59 baseline report/bundle fields, including the currently implemented bundle/report summary: 173 fields total.
- Defined 18 data classes: 3 allowed, 5 sensitive, and 10 prohibited.
- Required a six-sink canary strategy for every prohibited class.
- Added fail-closed behavior: missing baseline fields, unknown new fields, unknown classes, duplicate mappings, invalid paths, incomplete canary coverage, wrong task IDs, and oversized inventories are rejected.
- Added a threat-model document describing assets, threats, redaction order, hashing policy, and scope limits.
- Added the privacy validator to the normal GitHub Actions R0 matrix.
